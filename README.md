# DonPion — интернет-магазин цветов

Монорепозиторий из трёх независимых приложений:

| Папка | Что это | Стек | Порт по умолчанию |
|---|---|---|---|
| [`server/`](server) | Backend REST API | Node.js + Express + MongoDB/Mongoose | 4100 |
| [`client/`](client) | Витрина для покупателей | Next.js (App Router) + Tailwind CSS | 3000 |
| [`admin/`](admin) | Панель администратора (товары, категории, характеры, заказы) | Vite + React + Tailwind CSS | 5173 |

Клиент (`client`) и панель (`admin`) не подключаются к MongoDB напрямую — оба
общаются только с `server` по HTTP. Это даёт три полностью независимых
приложения, которые можно деплоить и масштабировать отдельно.

## 1. Backend (`server`)

```bash
cd server
cp .env.example .env
# впишите в .env свою строку подключения MongoDB (MONGODB_URI)
npm install
npm run seed     # категории-примеры, характеры для квиза и первый админ (без товаров — см. ниже)
npm run dev       # http://localhost:4100
```

После `npm run seed` в консоли появится логин и пароль созданного админа
(задаются в `.env` через `SEED_ADMIN_EMAIL` / `SEED_ADMIN_PASSWORD`). Именно
этими данными нужно входить в панель администратора. Товары сид **не
создаёт** — это боевая база, товары добавляются только через админ-панель с
реальными фото.

Основные эндпоинты:

- `GET /api/categories`, `GET /api/categories/:slug` — ботанические категории
  (Розы, Фиалки…) — прямая навигация по каталогу.
- `GET /api/characters`, `GET /api/characters/:slug` — варианты ответа в
  мини-квизе на главной («Романтичная и нежная» и т.д.) — привязываются к
  товарам, а не показываются отдельными плитками.
- `GET /api/products?category=&character=&search=&featured=&page=&limit=` —
  список товаров с фильтрами.
- `GET /api/products/:slug` — товар + похожие товары.
- `GET /api/settings` — редактируемый контент главной страницы (три фото
  hero: для компьютера, планшета и телефона).
- `POST /api/uploads` (admin, `multipart/form-data`, поле `images`, до 6
  файлов + текстовое поле `nameHint`) — загрузка фото с устройства. Сервер
  сжимает и переводит каждое фото в WebP (`sharp`, макс. ширина 2400px,
  качество 95) и сохраняет в `server/public/uploads/` под SEO-именем на
  основе `nameHint` — **не в MongoDB**: в базе хранится только путь вида
  `/uploads/imya-tovara-a1b2c3.webp`. Раздаётся статикой с кэшем на 30 дней.
- `POST /api/orders` — создать заказ (вызывается со страницы оформления).
- `POST /api/auth/login` — вход в админ-панель, отдаёт JWT.
- Остальные `/api/products`, `/api/categories`, `/api/characters`,
  `/api/orders`, `/api/settings` (POST/PUT/DELETE/PATCH) и `GET /api/*/admin/*`
  защищены JWT (`Authorization: Bearer <token>`) — ими пользуется только
  `admin`.

**Slug всегда генерируется сервером** из названия (кириллица
транслитерируется, см. `src/utils/slugify.js`) — ни один клиент (админка,
скрипты) никогда не отправляет `slug` при создании. При редактировании slug
не меняется, даже если название изменилось — старые ссылки не ломаются.

**Характер товара никогда не остаётся пустым**: если при сохранении товара
не отмечен ни один характер, сервер сам случайно назначает активный
характер (`ensureCharacters` в `products.controller.js`) — это реальное
сохранённое значение, админ видит его в форме и может изменить в любой
момент.

После каждого админского изменения (товар/категория/характер/настройки)
сервер сам «пингует» витрину (`notifyRevalidate.js` → `client`'s
`/api/revalidate`), чтобы изменения появлялись на сайте за секунду-две, не
дожидаясь истечения ISR-кэша.

## 2. Витрина (`client`)

```bash
cd client
cp .env.local.example .env.local
# NEXT_PUBLIC_API_URL должен указывать на запущенный server (по умолчанию http://localhost:4100/api)
npm install
npm run dev       # http://localhost:3000
```

Реализовано согласно ТЗ:

- **SSG + ISR** для страниц каталога (`/catalog/[category]`), характера
  (`/character/[slug]`) и товара (`/flowers/[slug]`) — `generateStaticParams`
  пререндерит все существующие страницы при сборке, `revalidate` (10 минут,
  плюс мгновенный сброс кэша по пингу от сервера) обновляет их в фоне без
  пересборки.
- **Чистые slug-адреса**: `/flowers/fialka-v-gorshke`, `/catalog/rozy` — без
  `?id=`.
- **JSON-LD**: `Product` (цена, `priceCurrency: "UZS"`, `availability`
  `InStock`/`OutOfStock`) на странице товара, `BreadcrumbList` на всех
  страницах через компонент [`Breadcrumbs`](client/src/components/Breadcrumbs.tsx),
  `Organization` в корневом layout.
- **Canonical-теги** — на каждой странице категории/товара через
  `alternates.canonical` в `generateMetadata`.
- **`sitemap.xml`** — рукописный route handler
  ([`src/app/sitemap.xml/route.ts`](client/src/app/sitemap.xml/route.ts)),
  а не типовой `sitemap.ts`: у типового хелпера нет поля под
  Google-расширение `<image:image>`, а для попадания фото товаров в Google
  Картинки оно важно. Плюс **`robots.txt`**
  ([`src/app/robots.ts`](client/src/app/robots.ts)). Оба генерируются
  автоматически из данных `server` (то есть из MongoDB) — вручную ничего не
  редактируется.
- **Уникальные тексты**: у каждой категории и товара есть отдельные поля
  `introText`/`story`, `seoTitle`, `seoDescription` в базе — это не шаблон
  с подстановкой имени, а собственный текст.
- **Фото товаров**: хранятся в MongoDB как путь (`/uploads/...`) или как
  внешняя ссылка (для обратной совместимости) — резолвятся в абсолютный URL
  через [`src/lib/images.ts`](client/src/lib/images.ts) везде, где нужен
  `next/image`, Open Graph или JSON-LD.
- Корзина и оформление заказа — клиентские страницы (`noindex`, не участвуют
  в SEO), корзина хранится в `localStorage`, заказ уходит в `server` через
  `POST /api/orders` (сервер сам пересчитывает цену по базе, не доверяя
  клиенту).

### Главная страница

- **Hero** — фото на весь экран, три независимых кадра под устройство
  (широкий для компьютера, квадратные для планшета и телефона — редактируются
  в админ-панели, раздел «Главная страница») через нативный `<picture>`, так
  что каждое устройство скачивает только своё фото. Заголовок «Искусство
  дарить эмоции»: на компьютере/планшете — белым текстом поверх фото с
  тенью, на телефоне — под фото на белой подложке, «Искусство дарить»
  графитовым, «эмоции» фирменным оранжевым. Кнопка «Подобрать букет» ведёт
  на мини-квиз.
- **Luxury Collection** — товары, отмеченные админом галочкой «Показывать в
  Люксовом»; на компьютере сетка 4 колонки со ссылкой «Смотреть всё» внизу
  (→ `/collection`), на телефоне/планшете та же лента с горизонтальным
  скроллом. Если ничего не отмечено — вежливое «Коллекция пополняется»
  вместо пустой секции.
- **Мини-квиз** ([`BouquetQuiz`](client/src/components/BouquetQuiz.tsx)) —
  вопрос про характер получателя, варианты ответа тянутся из `Character` в
  базе (новый характер в админке сразу появляется как вариант). Результат
  раскрывается тут же под вопросом — та же раскладка «сетка на компьютере /
  скролл на телефоне», без перехода на отдельную страницу.
- **Ритуал вручения** — согласование фото в Telegram, аквабокс и фирменная
  упаковка, календарь важных дат. Вместо типовых иконок «доставка 24/7».

## 3. Админ-панель (`admin`)

```bash
cd admin
cp .env.example .env
npm install
npm run dev       # http://localhost:5173
```

Отдельное SPA-приложение (SEO ему не нужен — `index.html` уже содержит
`<meta name="robots" content="noindex, nofollow">`). Вход по логину/паролю
(созданным через `npm run seed` в `server`), дальше:

- **Товары** — список, поиск, создание/редактирование/удаление. Фото
  загружаются прямо с устройства (кнопка «Добавить», превью, удаление по
  крестику) — никаких ссылок руками. Slug не отображается и не
  запрашивается — сервер генерирует его сам. Товар можно отметить одним или
  несколькими характерами для квиза и галочкой «Показывать в Люксовом» для
  секции Luxury Collection на главной.
- **Категории** — список, создание/редактирование/удаление, включая
  SEO-поля, вводный текст страницы категории и фото (тоже загрузка с
  устройства).
- **Характеры** — список, создание/редактирование/удаление вариантов ответа
  в мини-квизе на главной (название, описание).
- **Заказы** — список, детали заказа, смена статуса (`Новый` → `Подтверждён`
  → `Доставляется` → `Завершён` / `Отменён`).
- **Главная страница** — три отдельных фото hero (компьютер/планшет/телефон).

## Цветовая палитра и стиль

Единая тема во всех приложениях (`tailwind.config.ts` в `client` и `admin`):

- **`paper` (#FAF9F6)** — тёплый сливочно-белый фон, не стерильно-белый и не
  серый.
- **`ink` (#1A1A1A) / `graphite`** — глубокий графитовый текст. Заголовки —
  Playfair Display (включая настоящее лёгкое начертание, вес 400) с
  увеличенным трекингом (`tracking-luxe`), интерфейс и цены — Inter.
- **`hermes` (#F37021)** — единственный акцент, ярко и без затемнения:
  кнопки целевого действия, логотип DonPion (слово «Pion»), тонкая линия под
  шапкой при прокрутке, иконка корзины. Никогда не используется как заливка
  крупных блоков.
- Скругления ограничены 0–4px на уровне темы Tailwind (`borderRadius`) —
  даже если где-то в коде остался `rounded-full`, дизайн-система не даст ему
  превратиться в таблетку/скругление. Никаких теней и `backdrop-blur` —
  только фото, hairline-границы и типографика. Иконки — тонкая линия
  (`stroke-width: 1`). Единственное сознательное исключение — мягкий
  белый→прозрачный градиент за hero-заголовком на телефоне: явно
  запрошенный, локальный эффект, а не общий стиль карточек.
- Никаких «скидочных» плашек — старая цена (если есть) показывается тихо,
  зачёркнутым текстом рядом с новой, без кричащих бейджей.
- Мягкая анимация появления: `template.tsx` в App Router перезапускает
  CSS-анимацию `.page-transition` при каждом переходе между страницами,
  hero-фото на главной дополнительно плавно проявляется через
  `.photo-fade-in`.

## Что нужно сделать перед продакшеном

1. Подставить реальный `MONGODB_URI` в `server/.env` (Atlas или свой
   кластер) — сейчас используется локальный/туннелированный MongoDB.
2. Сменить логин/пароль админа с временных `1` / `1` на что-то настоящее —
   через `SEED_ADMIN_EMAIL`/`SEED_ADMIN_PASSWORD` перед пересидированием,
   либо напрямую в базе.
3. Наполнить каталог настоящими товарами через админ-панель — база
   специально держится пустой от демо-товаров (`npm run seed` создаёт
   только категории, характеры и админа).
4. Загрузить в админ-панели реальные фотографии для категорий и трёх кадров
   главного фото (`Settings`) — сейчас там Unsplash-плейсхолдеры.
5. Задать `JWT_SECRET` и надёжный `REVALIDATE_SECRET` (одинаковый в
   `server/.env` и `client/.env.local`) в проде.
6. При деплое `client` на Vercel/другой хостинг задать `NEXT_PUBLIC_API_URL`
   и `NEXT_PUBLIC_SITE_URL` (последний используется для canonical, sitemap и
   JSON-LD) на реальные адреса, и добавить реальный домен `server` в
   `images.remotePatterns` в `client/next.config.mjs`.
7. Ограничить CORS в `server/.env` (`CLIENT_URL`, `ADMIN_URL`) продовыми
   доменами.
8. Для `server/public/uploads` в проде убедиться, что диск персистентный
   (не эфемерная файловая система) — при переезде на serverless-хостинг
   для сервера стоит вынести хранение фото на S3-совместимое хранилище.
